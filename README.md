# Internship Checker

CLI-приложение на Go, которое мониторит сайты компаний на наличие открытых стажировок и отправляет уведомления подписчикам в telegram.

## Описание

Приложение запускается как фоновый процесс и каждый час обходит заданный список сайтов с помощью headless-браузера (Chromium через chromedp). Если на странице найдено ключевое слово, означающее открытие набора, бот рассылает уведомление всем пользователям, подписавшимся на эту компанию.

Пользователи управляют подписками через Telegram: после команды `/start` открывается интерактивное меню с кнопками. Повторное нажатие на кнопку отменяет подписку.

## Структура проекта

```
internship/
├── main.go                  # Точка входа, настройка сайтов, запуск горутин
├── bot/
│   └── bot.go               # Telegram-бот: меню, обработчики, рассылка
├── checker/
│   └── checker.go           # Проверка сайтов через headless Chromium
├── health/
│   └── health.go            # HTTP /health эндпоинт
├── storage/
│   ├── storage.go           # Реализация работы с PostgreSQL
│   ├── interface.go         # Интерфейс IStorage
│   └── mock.go              # Mock-реализация для тестов
├── Dockerfile               # Образ приложения
├── docker-compose.yml       # Оркестрация: приложение + PostgreSQL
├── .env.example             # Шаблон переменных окружения
└── go.mod
```

Компоненты запускаются конкурентно:

- `bot.Start()` — в отдельной горутине (long polling Telegram)
- `health.StartServer()` — в отдельной горутине (HTTP-сервер на :8080)
- Основной поток — ticker, запускающий проверку сайтов раз в час с `sync.WaitGroup` для параллельных запросов

## Установка и запуск

**1. Клонировать репозиторий**

```bash
git clone https://github.com/aqvilov/internship-checker
cd internship
```

**2. Установить зависимости**

```bash
go mod tidy
```

**3. Запустить**

```bash
go run main.go
```

Или собрать бинарный файл:

```bash
go build -o internship-bot .
./internship-bot
```

## Запуск через Docker

Проект поставляется с `Dockerfile` и `docker-compose.yml`. Docker Compose поднимает два сервиса: приложение и PostgreSQL.

**1. Создать файл окружения**

```bash
cp .env.example .env
# указать TG_TOKEN; DATABASE_URL задаётся автоматически через docker-compose
```

**2. Собрать и запустить**

```bash
docker compose up --build
```

Для запуска в фоне:

```bash
docker compose up --build -d
```

**3. Остановить**

```bash
docker compose down
```

Чтобы также удалить volume с данными PostgreSQL:

```bash
docker compose down -v
```

**Переменные в docker-compose**

`docker-compose.yml` передаёт в контейнер `TG_TOKEN` из `.env` и формирует `DATABASE_URL` самостоятельно, указывая на сервис `db`. Менять `DATABASE_URL` в `.env` при использовании Docker не требуется.

**Health Check**

После запуска эндпоинт доступен на хосте:

```
GET http://localhost:8080/health
```

## Как это работает

**Регистрация пользователя**

При отправке команды `/start` бот сохраняет `chat_id` пользователя в таблицу `users` и отображает меню выбора компаний.

**Управление подписками**

Каждая кнопка в меню соответствует одной компании. Нажатие переключает состояние подписки (подписаться / отписаться). Активные подписки отмечены в метке кнопки и перечислены в тексте меню.

**Проверка сайтов**

Раз в час `time.Ticker` запускает параллельную проверку всех сайтов. Каждая проверка:

1. Открывает страницу через headless Chromium
2. Ожидает загрузки `body` и дополнительные 2 секунды для JS-рендеринга
3. Ищет ключевое слово в тексте страницы (регистронезависимо)

**Отправка уведомлений**

Если ключевое слово найдено, метод `NotifyAll` рассылает сообщение всем подписчикам данной компании. Повторная отправка по одному и тому же сайту в рамках одной сессии исключена (флаг `notified`).

**Схема базы данных**

Таблицы создаются автоматически при первом запуске:

```sql
CREATE TABLE IF NOT EXISTS users (
    chat_id BIGINT PRIMARY KEY
);

CREATE TABLE IF NOT EXISTS subscriptions (
    chat_id   BIGINT,
    site_name TEXT,
    PRIMARY KEY (chat_id, site_name)
);
```

После запуска HTTP-сервер доступен на порту `8080`:

}
```

{

  "database": "unavailable"

```

## Добавление новых сайтов

Сайты для мониторинга задаются в `main.go` в слайсе `sites`:

```go
sites := []checker.Site{
    {Name: "Авито", URL: "https://start.avito.ru/", Keyword: "набор открыт"},
    {Name: "Т-Банк", URL: "https://education.tbank.ru/start/go/", Keyword: "подать заявку"},
    // Добавьте новую запись:
    {Name: "Название", URL: "https://example.com/", Keyword: "ключевое слово"},
}
```

- `Name` — отображаемое название в Telegram-меню
- `URL` — адрес страницы для проверки
- `Keyword` — слово или фраза, наличие которых означает открытый набор (поиск без учёта регистра)

## Тестирование

Пакет `storage` содержит интерфейс `IStorage` и его mock-реализацию `MockStorage`, что позволяет тестировать логику бота без подключения к базе данных.

```go
mock := storage.NewMock()
// передать mock вместо реального хранилища
```

Для запуска тестов:

```bash
go test ./...
```
